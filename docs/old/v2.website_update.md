# PixeSci website content update v2 — Agentic Compliance Operating System repositioning brief

**Purpose of this document.** `pixesciweb` (pixesci.com) was last brought up to
date by `v1.website_update.md`, which added seven `/platform/*` module pages
(Laboratory, Quality Management, Materials & Products, Manufacturing Quality,
Equipment, Documents & Training, Reports & Analytics) so the site would describe
the regulated-operations depth `pixesciv2` had grown into. That brief was fully
implemented and remains accurate — but it describes the *substrate*: the record
types and workflows PixeSci tracks. It does not describe the thing that now makes
PixeSci different from a regulated system-of-record product: a real, working,
governed AI agent layer that continuously watches the Quality Unit's systems,
flags the same kinds of gaps regulators cite, and produces evidence — and it does
not carry the company's current strategic positioning, which has moved from
"connect and automate scientific software" to **"the agentic compliance operating
system for the Quality Unit."**

This document is a complete, self-contained brief for that repositioning. Like
`v1.website_update.md`, it is written so a developer (human or AI) can implement
it directly: real drafted copy, not placeholders, for every new and rewritten
page, and file-path-cited evidence for every product claim. It was produced by
(1) reading `pixesciv2`'s backend and frontend source in full for the agent
orchestrator, safety gate, deterministic compliance rules, audit chain, evidence
export, roles, and integrations; (2) reading `pixesciweb`'s own source, design
system, and both prior implementation prompts (`../../WEBSITE_PROMPT.md` and
`v1.website_update.md`) in full, to match its content model, voice, and design
system exactly; and (3) reading three pieces of source-of-truth positioning
material the CEO provided: `PixeSci-Brief.pdf` (a September 2026 Lean Canvas
— the current, authoritative strategic positioning), `docs/10 REGULATORY
PRINCIPLES.pdf` (a printed one-pager already using the brand line "PixeSci™ — The
Agentic Compliance Operating System," listing ten FDA/EMA-sourced AI-governance
principles), and an AI-generated reference screenshot the CEO produced as loose
visual inspiration only — explicitly **not** to be copied.

**Scope.** This brief only describes changes to `pixesciweb`'s public marketing
site: `src/app/(site)/*` and its supporting `src/components/{site,sections,
visuals}` and `src/content/*`. It does not touch, and is not informed by needing
to touch, `pixesciweb`'s own Admin Portal (`src/app/admin/*`) or Client Portal
(`src/app/portal/*`) — those are a separate product surface in the same repo.
`pixesciv2` is not modified at all; it was only read, the same way v1 read it.

**What changed since v1, in one paragraph.** `pixesciv2` now has a real
multi-mixin AI agent orchestrator with a capability registry, risk-tiered
approval gates, and a safety gate that force-requires human approval before any
action that could touch a live instrument; eleven deterministic compliance rules
continuously evaluating a canonical event ledger for the same failure patterns
regulators cite (missing raw data, unreconciled reruns, shared/privileged
account activity, deletion of regulated data, and more); a governed
"audit/inspection copilot" whose authority boundary — it can never approve,
close, release, invalidate, sign, or write to a source system, only recommend —
is enforced in code and checked by an automated evaluation suite, not just
described in a policy document; a live, on-demand-verifiable hash-chained audit
trail; SHA-256-manifested evidence-bundle export per finding; a Part 11 / GMP /
ISO 13485 / ALCOA+ "Compliance & Validation" workbench; and an expanded role
catalog spanning execution, review, administration, training, audit, and
executive-oversight personas. None of this exists anywhere on the current
website. This brief closes that gap, while correcting one framing error carried
over from v1: PixeSci is not positioned as a replacement for a customer's LIMS,
QMS, CDS, or instrument software — current, CEO-approved strategy is explicit
that PixeSci is **an orchestration and evidence layer that runs behind the
systems a customer already has**, not a rip-and-replace system of record.

**Voice, one more time before you write anything.** Nothing about voice changes
from `v1.website_update.md` or `../../AGENTS.md`: plain, concrete, second-person; no
hype adjectives ("revolutionary," "seamless," "powerful," "cutting-edge"); no
unqualified regulatory promises ("compliant," "validated," "certified,"
"guaranteed," "FDA-approved"); short, literal, subject-verb-object sentences
over marketing abstraction; every regulated-sounding claim paired with the
existing validation-responsibility disclaimer pattern. The one addition this
brief makes to voice rules: **describe the AI plainly and specifically as a
governed system with an enforced authority boundary, not as an autonomous
decision-maker.** Every AI-related claim on the site should make clear that a
qualified human owns every regulated decision — this is not a hedge, it is the
actual architecture, and it is PixeSci's strongest, most defensible
differentiator against "generic AI chat." Match this voice exactly in anything
you write beyond what's drafted here.

**One explicit, non-negotiable content rule for this update.** Where this brief
references the kinds of findings that appear in FDA warning letters (used
throughout as risk-education content, consistent with the Lean Canvas listing
"FDA warning-letter and practical quality education content" as a sanctioned
marketing channel), **do not name any company, do not cite a specific warning
letter, and do not attach a specific date or docket to any example.** Every
example must be a generic, anonymized *finding pattern* (e.g., "a lab's
chromatography audit trail showed a reinjection with no documented
justification"), phrased so it cannot be traced to any single real
inspection or company. This is a firmer rule than v1 or the Lean Canvas
required, and it applies to every page, FAQ entry, and visual in this brief —
if you find yourself tempted to name a company or cite "a 2024 warning letter
to [company]," stop and rewrite it as a category.

## 1. Executive summary

### 1.1 The gap

The current site tells a "connect and automate scientific software" story
(hero: "Talk to your lab!") plus, since v1, a "here are the seven regulated
modules we track" story. Both are true and neither is wrong — but neither is
the company's current lead pitch. The CEO's own September 2026 Lean Canvas
repositions PixeSci as **"the agentic quality control operating system for
regulated life-science companies"** — matching the brand line already printed
on the company's own outreach collateral, **"PixeSci™ — The Agentic Compliance
Operating System."** The core thesis, in the Lean Canvas's own words:

> "Regulated QC is fragmented across instruments, software, people, procedures,
> equipment, environmental systems, and external partners. Manual handoffs break
> continuity between execution and evidence. Small gaps become expensive when
> they are discovered late. PixeSci operates behind the existing stack to carry
> context, controls, approvals, and evidence through the workflow as it
> happens." — "From retrospective reconstruction to prospective, continuous
> quality. No new instruments. No rip-and-replace software. One governed
> execution layer across the Quality Unit."

None of the product evidence behind that story is on the site today: not the
agent orchestrator, not the deterministic compliance rules, not the safety
gate, not the governed audit copilot's enforced authority boundary, not the
hash-chained audit trail, not the evidence-bundle export. A prospective buyer
searching for "agentic compliance software," "continuous quality monitoring,"
or "AI compliance copilot for pharma" has no reason to find PixeSci, and a
buyer who does land on the site sees a workflow-automation and record-keeping
tool, not a governed AI layer watching the Quality Unit continuously. That is
the gap this brief closes.

### 1.2 The approach

1. **Rebuild the homepage** around the Lean Canvas narrative: fragmented QC →
   evidence gaps → expensive, retrospective consequences, versus PixeSci's
   continuous, governed alternative — with a real, disclaimed risk calculator
   as the interactive centerpiece the CEO asked for.
2. **Add one new Platform page**, `/platform/agents`, as the flagship deep-dive
   on the governed AI layer itself — the single biggest content gap, and the
   thing that most differentiates PixeSci from every "regulated system of
   record" competitor.
3. **Rewrite `/compliance`** from a narrower ALCOA/data-integrity page into the
   anchor page for the orchestration-and-evidence-layer story.
4. **Rewrite `/integrations`** to separate what's actually connected today
   (native modules, an open-source CDS connector, an instrument CSV gateway)
   from the documented target catalog of major commercial CDS/instrument
   vendors — a genuine "do not oversell" gap in the current framing.
5. **Reweight, not replace, the rest of the site.** The seven existing
   `/platform/*` pages stay — they are accurate and valuable SEO surface area —
   but get a light-touch reframe as the native-module depth *underneath* the
   orchestration story, with one corrected claim (Laboratory's FAQ currently
   implies PixeSci can run "in place of a separate LIMS"; the current
   positioning is explicit that PixeSci is not a replacement). Solutions pages
   are reweighted to match the Lean Canvas's explicit, narrower beachhead ICP.
6. **Update `../../AGENTS.md`** alongside the content so the living style guide
   doesn't drift out of sync with the new positioning, the calculator's
   disclaimer rules, and the anonymized-FDA-content rule.

### 1.3 What NOT to do

- Don't claim PixeSci prevents FDA warning letters, recalls, import alerts, or
  product failures, anywhere, in any phrasing. The Lean Canvas's own dollar
  figures are explicitly labeled internal illustrative models, not predictions
  or guarantees — preserve that framing exactly everywhere it's reused.
- Don't name a company, cite a specific warning letter, or attach a specific
  date/docket to any FDA-risk-education example. Category-based, anonymized
  patterns only (see the non-negotiable rule above).
- Don't imply PixeSci replaces a customer's LIMS, QMS, CDS, or instrument
  software. It runs behind and across them. Where the seven existing Platform
  pages currently imply otherwise (Laboratory's FAQ is the clearest instance),
  correct the copy.
- Don't imply the AI approves, closes, releases, invalidates, signs, or
  otherwise makes a regulated decision on its own. This boundary is enforced in
  the product's own code (see §16.1) — say so plainly and don't soften it into
  vague "human-in-the-loop" language when the more precise, more credible claim
  is available.
- Don't oversell the integrations catalog. Only native PixeSci modules, the
  OpenChrom CDS connector, and the balance/pH-meter/qPCR CSV gateway are live
  today. Waters Empower, Agilent OpenLab, Thermo Chromeleon, Shimadzu
  LabSolutions, and the other eight vendors in the target catalog are
  documented, planned connectors — the product's own code says so explicitly
  ("No live connector is implemented yet"). Say "designed to connect with" or
  "on our integration roadmap," never "connects with" or "integrates with," for
  anything in that target list.
- Don't publish exact dollar pricing figures on the public site (see §18 —
  this is a judgment call, flagged as a recommendation, not implemented as a
  strict rule the way the other items above are).
- Don't invent customer logos, adoption numbers, or ROI statistics. The product
  is pre-broad-launch with one named early design partner under NDA-adjacent
  terms; the product's own internal metrics service explicitly refuses to
  claim automation savings "without an approved baseline and methodology" (see
  §16.1) — the website should hold itself to the same standard.
- Don't introduce new visual language or a new component framework. Reuse
  `.site-container`, `.section-space`, `.eyebrow`, `.visual-frame`,
  `.visual-toolbar`, `FeatureGrid`, `MarketingPage`, and the existing OKLCH
  color tokens. New illustrative visuals continue the hand-built-mockup style
  of `src/components/visuals/*` — CSS/Tailwind-drawn UI, not real screenshots,
  denser and more dashboard-like than today's mockups where the new content
  calls for it, but built the same way.

Pass `disclaimer` — this page touches AI-driven detection and compliance

### 4.2 Visual density: continuing the mockup approach, raised one notch

The CEO's reference screenshot is not to be copied, but its *feel* — a denser,
more data-rich "operations dashboard" look, with small colored status chips
and metric tiles — is a reasonable target for the new content's visuals,
**built the same way every existing visual is built**: hand-coded
React/Tailwind using `.visual-frame` / `.visual-toolbar` chrome, the OKLCH
tokens, `lucide-react` icons, no real screenshots, no exposed internal
architecture (per `../../AGENTS.md`'s existing, still-binding rule). Where this
brief's new content calls for a visual, prefer:

- more metric tiles per view (4–6, not the 4 the existing `dashboard-visual.tsx`
  uses) where the content genuinely has that many real, distinct things to show
  (§6.4's `agent-orchestrator` visual is the main example);
- small colored status chips (amber/emerald/rose, matching the destructive/
  ring tokens already in `globals.css`) for rule/finding severity, echoing the
  Lean Canvas's own red/blue/green category-card treatment without copying its
  layout;
- the same restrained, non-decorative motion rules as `hero-agent-mockup.tsx`
  (respect `prefers-reduced-motion`, no motion for its own sake).

Do not add a new "browser chrome" or "realistic app window" treatment beyond
what `.visual-frame`/`.visual-toolbar` already provide — that would start to
look like a screenshot, which `../../AGENTS.md` and the product's own confidentiality
posture both rule out.

## 7. The risk calculator

### 7.1 What it is and isn't

This is the one component in this brief that doesn't exist anywhere in either
repo today — build it fresh, as a client-side-only React component (no backend
call; `../../AGENTS.md` §"Coding Standards" already forbids adding backend calls for
marketing content without an explicit request, and there's no reason to break
that rule here — every input and formula below can run in the browser).

It is **not** a lead-capture form (no email/contact fields, no submission —
matches `../../AGENTS.md`'s "no self-service account registration, file upload, or
contact form" rule) and it is **not** a precision financial model. It has two
outputs, deliberately kept separate so the calculator never implies more
precision than the underlying data supports:

1. **Your routine compliance tax** — computed live from the visitor's own
   inputs, using plain arithmetic (hours × rate). This part is a genuine,
   defensible calculator.
2. **Remediation exposure if a gap reaches inspection** — two fixed reference
   bands, not computed from the visitor's inputs, reproducing the Lean
   Canvas's own two disclosed illustrative scenarios verbatim. This part is
   reference education, not a personalized prediction, and must be labeled as
   such.

Never blend the two into one combined number, and never imply part 2 is
computed from the visitor's own inputs — that would fabricate a precision
mapping from "systems you connect" to "dollars at risk" that has no real basis
behind it. Keeping them visually and functionally separate is the load-bearing
design decision of this whole component.

### 7.2 Inputs

| Field | Type | Default | Notes |
|---|---|---|---|
| Investigations or deviations per month | number | `4` | OOS, OOT, deviations, and nonconformances combined |
| Average investigation time (hours) | number | `12` | Per event, including reconciliation and write-up |
| Hours per month on manual reconciliation & audit prep | number | `20` | Time spent cross-checking records across systems |
| Loaded hourly cost (USD) | number | `85` | Fully-loaded cost of QA/QC analyst time; label as an estimate the visitor should adjust |

Keep this to four fields — the CEO's reference screenshot uses six or more,
but every additional field increases the temptation to imply a precision the
underlying model doesn't have. Four real, easily-estimated inputs is enough
for a genuine calculation and keeps the component usable on mobile (per
`../../AGENTS.md`'s responsive rules).

### 7.3 Output 1 — Your routine compliance tax (computed)

```
monthlyHours = (investigationsPerMonth × avgInvestigationHours) + reconciliationHoursPerMonth
annualHours = monthlyHours × 12
annualCost = annualHours × loadedHourlyCost
```

Display as a single large figure, labeled **"Estimated annual compliance
tax"**, with the formula's plain-language breakdown underneath (e.g. "48
investigation-hours + 20 reconciliation-hours per month × 12 months × $85/hour
= …") so the visitor can see exactly how the number was built — this
transparency is itself a trust signal and matches the site's existing "show
your work" voice (e.g. how `/compliance` explains ALCOA rather than asserting
compliance).
